# Knowledge graph — habits-tracker-web

Static map of the codebase: entities (files, DB tables, external services) and the
relations between them (`imports`, `queries`, `calls`). The machine-readable version
lives in [`knowledge-graph.json`](./knowledge-graph.json) (115 nodes, 302 edges),
generated by static analysis of import specifiers, `supabase.from('…')` calls and
outbound HTTP hosts.

## 1. Layers

```
middleware/proxy.ts ──auth gate──▶ app/(auth)/*   app/(app)/*   app/api/*
                                        │             │            │
                                        ▼             ▼            ▼
                                    components/*   components/*   lib/validation
                                        └──────┬──────┘            lib/rate-limit
                                               ▼                        │
                                        lib/* (domain)  ◀───────────────┘
                                               │
                                    lib/supabase/{client,server,admin}
                                               │
                                        Supabase (Postgres + RLS)
```

| Layer | Nodes | Rule |
|---|---|---|
| `route` — `app/(app)`, `app/(auth)`, layouts | 28 | Client Components; read data through `lib/*` with the **browser** Supabase client |
| `api` — `app/api/**/route.ts` | 7 | Server handlers; every one goes through `lib/rate-limit` + `lib/validation/schemas` |
| `component` — `components/**` | 36 | Presentational + form logic; never touch Supabase directly except `CalendarView`, `RoutinePlanningPanel`, `SessionView`, `Sidebar` |
| `lib` — domain modules | 19 | The only place SQL-ish access lives |
| `data-client` — `lib/supabase/*` | 3 | `client` (browser), `server` (RSC/route, `cookies()`), `admin` (service role, ingest only) |
| `table` — Supabase tables | 12 | All RLS-scoped to `auth.uid() = user_id` |
| `external` | 6 | OpenAI, Google Calendar, Google OAuth, Google Health Connect, Upstash Redis, Sentry |

## 2. Hub nodes (highest degree)

| Node | Degree | Role |
|---|---|---|
| `lib/types.ts` | 45 | Single source of truth for every domain type; imported by nearly every route and component |
| `lib/supabase/client.ts` | 27 | Browser data access — the app is client-query-first |
| `lib/i18n.tsx` | 26 | en/fr/ar strings + `useLocale()`; UI text funnel |
| `lib/routines.ts` | 19 | Largest domain module (22 exports): routine CRUD + live session state machine |
| `lib/goals.ts` / `lib/habits.ts` | 18 / 17 | Goal ↔ habit ↔ routine linking, streaks, toggles |
| `lib/utils.ts` | 14 | `cn()`, date helpers (`TODAY`, `dateStr`, `toISODate`) |
| `components/habits/HabitForm.tsx` | 15 | Fan-out to 9 type-specific subforms via `TypePicker` |

Removing `lib/types.ts`, `lib/supabase/client.ts` or `lib/i18n.tsx` would fracture the
graph — they are the three articulation points.

## 3. Domain entities and their relations

```
User ──owns──▶ Habit ──logged as──▶ HabitLog (per day)
  │              ▲                     │
  │              │ linked via          └──feeds──▶ streaks, discipline score
  │           goal_habits
  │              │
  ├──owns──▶ Goal ──goal_routines──▶ Routine ──has──▶ RoutineTask[] (JSONB)
  │                                     │                 types: reps | time | bilateral | resource
  │                                     └──scheduled by──▶ schedule_days[] (0–6)
  │                                     └──run as──▶ RoutineSession (UNIQUE user+routine+date)
  │                                                     completed_task_ids[]  ("taskId:right" / ":left")
  ├──owns──▶ DailyCheckin (mood / energy / focus → body, mind, soul pages)
  ├──owns──▶ CalendarEvent ──linked_habit_ids[]──▶ Habit,  google_event_id ──▶ Google Calendar
  └──owns──▶ HealthReading (steps, sleep, HR, HRV, calories, weight)
                 ▲ ingested via health_sync_tokens + /api/health/ingest (service role)
```

Habit types: `simple | workout | reading | study | shift | meditation | prayer | journaling | body_metric`
— each carries a `*Metadata` shape in `habits.metadata` JSONB rendered by a dedicated subform.

## 6. Invariants worth keeping

1. **Auth gate is one node**: `proxy.ts` (re-exported by `middleware.ts`) — unauthenticated → `/login`,
   authenticated on an auth page → `/dashboard`, `/` always redirects.
2. **API routes always pair** `lib/rate-limit` with a zod schema from `lib/validation/schemas`.
   Every one of the 7 route handlers currently does; a new one that skips either breaks the pattern.
3. **Only `/api/health/ingest` uses `lib/supabase/admin.ts`** (service role). Nothing else should.
4. **Nav is a two-node update**: adding a page requires both `components/layout/Sidebar.tsx`
   and `components/layout/BottomNav.tsx` (plus `MoreSheet` overflow).
5. **Migrations mirror the live DB 1:1** — `supabase/migrations/` is the source of truth.
6. `CalendarView` is the only `dynamic()` import (FullCalendar is client-only, ~521 LOC).
