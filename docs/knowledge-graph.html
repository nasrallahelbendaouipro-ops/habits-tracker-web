Domain model

  • Habit → habit_logs per day; 9 types, each with a *Metadata JSONB shape and its own subform.
  • Routine holds tasks JSONB + schedule_days[]; a run is a RoutineSession, unique on (user, routine, date), tracking completed_task_ids[] — bilateral tasks store id:right / id:left.
  • Goal links to habits and routines through the goal_habits / goal_routines join tables.
  • DailyCheckin feeds the body / mind / soul pages; HealthReading arrives from the iOS Shortcut through a per-user sync token.
  • CalendarEvent carries linked_habit_ids[] and an optional google_event_id.

Invariants

  1. The auth gate is a single node — proxy.ts, re-exported by middleware.ts.
  2. Every API route pairs lib/rate-limit with a zod schema from lib/validation/schemas. All 7 currently do.
  3. Only /api/health/ingest touches the service-role client lib/supabase/admin.ts.
  4. Adding a page means editing both Sidebar.tsx and BottomNav.tsx.
  5. supabase/migrations/ must stay 1:1 with the live database.
  6. CalendarView is the only dynamic() import — FullCalendar is client-only.
